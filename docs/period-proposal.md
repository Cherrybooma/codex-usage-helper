# 周记录与月核算：待讨论方案

本文件记录方案，不是当前计量实现。当前桌面账本仍使用 Asia/Shanghai 自然周，月核算尚未启用。

## 同一份记录，两种汇总

推荐项目周报按周一 00:00 到下周一 00:00，方便任务、产出与投入比较；月核算按经确认的实际续费账期起点到下一账期起点。若选择自然月，则按月初到下月初，并明确标为自然月而不是会员账期。

周、月只是对同一份已接受用量重新分组，不各存一套相加的原始消耗。一个月不等于四周；跨月的周只取落在月度边界内的记录。边界采用开始包含、结束不包含，避免相邻周期重复计数。

以月中续费为例，一个月度账期可能跨越多个自然周。月度总数应直接按记录时间求和，不能整段相加五份周报，也不能平均分摊到天。账期精确到时间时应从本机原始计量事件复算边界，不能从日摘要猜测半天的消耗。

## 官方额度另用真实窗口

官方额度百分比与本机 Token 是不同数据。额度观测保留 API 提供的窗口时长、reset 时间和已用百分比，不推定第一次充值就是额度周期起点。

额度在自然周中提前重置时，记录重置前后实际观测到的增量和缺口，不把重置本身算作新增使用 100%。首次采集、离线及重置前缺少读数时保留不完整标识。月度 Token 可求和，额度百分比不能当作相同基准直接累加成“本月完成率”。

[OpenAI 官方用量说明](https://learn.chatgpt.com/docs/pricing#what-are-the-usage-limits-for-my-plan)说明用量取决于模型、任务、上下文等，并要求查看实际限额与重置时间；该资料未证明个人充值时刻与额度窗口起点绑定。

## 还需确定

1. 项目周报是否采用上述自然周建议，或选择跟随官方窗口。
2. 月核算采用实际会员账期还是自然月；若采用账期，需要确认具体续费起止。
3. 原先未采集的额度历史保持缺失；仅同步本周起的 Notion 日摘要不能声称覆盖完整历史月。

Token 投入不等于订阅余额、最终账单或项目收益。这里的月核算用于比较一个付费周期内做出了哪些成果、记录了多少投入，不把订阅费用伪装成每个项目可精确分摊的账单。
