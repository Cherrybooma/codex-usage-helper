# 周记录、月核算与额度窗口

已确认采用三种口径：项目周报按上海自然周，额度按 Codex 实际返回的窗口，会员月核算按经确认的续费账期。周期账本独立于具体项目管理页面，在 Notion「周期与额度」页面查看。

## 同一份记录，两种 Token 汇总

自然周从 Asia/Shanghai 周一 00:00 到下周一 00:00。会员月从最近一次已确认续费时刻开始，按同一天、同一时间向前或向后推算月度边界；不是固定 30 天，也不是四周。若续费日在某月不存在，使用该月最后一天，下一月仍从原续费日推算。例如 1 月 31 日的下一边界是 2 月末，之后回到 3 月 31 日。

边界均为开始包含、结束不包含，当前周期只计入本次扫描终点之前的记录。周和月都是同一份已接受用量的不同视图，不能相加。一个月跨过几份周报时，也不能把整周总数相加或平均分摊到月；程序按每条记录的内部时间重新归入账期。

周期核算完整重放本机保留日志，使用扫描器统一的计数、去重和归因路径。旧版累计记录在窗口之前的历史仍用于建立差分基线。缓存输入、推理输出等细分不再加进总数，优先保留原记录的 `total_tokens`。每个周期提供项目、模型与上海日期汇总，以及该周期内去重的会话数；跨日会话数不能直接相加。

默认输出当前及此前共 12 个自然周；配置续费锚点后，输出当前及此前共 12 个会员月。这个数量限制汇总视图，不删除原始日志或已经同步的更早 Notion 历史。

## 续费锚点与估算范围

在应用菜单的「周期核算…」中填写最近一次已发生的会员续费日期。必须来自可确认的续费或付款记录，不能从 Codex 重置时间推断，也不会自动用今天代替。

本地 `widget/data/app-settings.json` 保存：

| 设置 | 含义 |
| --- | --- |
| `billing_anchor` | 带时区的 ISO 续费锚点 |
| `billing_anchor_precision` | `datetime`：已知日期与时间；`date`：只知道日期 |
| `billing_timezone` | 固定为 `Asia/Shanghai` |

只知道日期时按上海时间当天 00:00 划分，并明确标为日粒度估算；这不是精确付款时刻。锚点之前的历史月、以及由锚点推算的其他月份，在本地报告保留 `extrapolated_schedule` 边界标识；Notion 边界说明同样注明按锚点推算，不能当成每次真实续费已核对的账单。暂停会员、改订阅日或其他实际账期变化需要重新确认锚点。

未提供、无时区、无效或未来的锚点使月核算保持 `needs_anchor`，不补造零用量的月份。只有实际续费锚点经确认后，才可验证个人月度数值；模拟边界测试通过不代表个人月账期已验证。

## 官方额度使用独立窗口

额度百分比来自官方已返回的观测，不从 Token 倒推。窗口保留时长、重置时间、末次已用／剩余读数、观测时间与缺口；窗口开始按「重置时间减窗口时长」反推，并标明依据。当前与已结束窗口分别记录，不用自然周或会员账期覆盖实际窗口。

本机周期报告包含当前窗口和最近 30 个有用量的历史窗口；旧的全零空闲窗口从摘要视图省略，完整 SQLite 观测保留。`0% → 0%` 的截止时间滚动不计为重置。更早的 Notion 历史不会因退出最近列表被删除。缺少初始读数、采集间隔、计数下降、容量或类别变化标记观测不足；末次剩余不等于结束时最终未用额度。

Notion 中被较新同类窗口替代的旧记录会退出“进行中”，仍保留原读数、观测时间和预计重置时间。“已结束”在这里也表示该观测窗口已被替代，不证明真实切换时刻或最终消耗；说明字段会区分这种情况。旧报告不能重新打开较新的窗口，也不会改变其他本机来源的记录。

本周超额仍只累计已观测使用增量，重置本身不记成新增 100%；不同容量和不同窗口的百分比不能直接相加为本月使用率或余额。官方用量与本机 Token 不代表同一种量。[OpenAI 官方用量说明](https://learn.chatgpt.com/docs/pricing#what-are-the-usage-limits-for-my-plan)要求查看实际限额与重置时间，不能据此认定个人续费时刻就是额度起点。

## 本地刷新与 Notion 记录

本机周期 Token 汇总最多缓存 5 分钟；修改续费设置会使旧账期缓存失效。额度观测从已保存的历史独立更新，不因 Token 缓存而固定在旧时刻。设置中的「刷新核算」或下面的命令会强制重算：

```sh
mkdir -p validation
python3 widget/widget_backend.py --accounting-summary --output validation/accounting.json
```

`validation/` 和 `widget/data/` 被 Git 忽略。导出含用量与归因元数据，可能包括私人项目名称；应留在本机，不公开发布真实报告。

启用 Notion 并已有周期账本配置后，常规同步发送项目每日及周／月 Token 摘要。额度窗口默认留本机，不再自动扩充云端；已有云端审计与待发送队列保留：

```sh
python3 widget/widget_backend.py --sync-notion --force-sync
```

显式添加 `--quota-window-audit` 才同步可选额度审计到已有库，不会因普通同步新增独立额度页。本机模式在读取凭据与联网前拒绝同步。周期摘要采用绝对替换，Token／质量未变而时间推进时不重复写；历史对账通常每天一次，恢复、键集合变化或强制同步立即核查。周期失败独立报错，不阻止项目每日摘要。已有两库不设 Project 关系；更换月锚点保留旧方案作审计，取消旧 `Included`、将 `Counted Tokens` 归零，未配置锚点不删除历史。见 [Notion 说明](notion.md#独立周期与额度页面)。

Token 投入不等于订阅余额、最终账单或项目收益。报告保留响应计数、旧格式估算、无法读取与窗口内无用量的区别；本机保留记录不能证明覆盖完整账户或订阅历史。

月底续费需要确认原续费日。例如短月份的30日扣费，不能单凭这一笔断定原续费日是30日还是31日；设置中应选择能表达原续费日的锚点。
