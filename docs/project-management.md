## 合并既有适配

先停止参考副本的发布后台，再运行迁移对照。下面命令只展示做法；不要在已有迁移完成的环境反复重建数据：

```sh
.venv/bin/python3 scripts/migrate-markdown.py \
  --reference-root "$HOME/Documents/项目管理系统" \
  --vault "$HOME/Documents/项目管理obsidian"
```

默认只读比较，不写入管理库或运行配置。核对绑定和未决项后，同一命令加 `--apply` 接管；未决旧 Notion 对应关系、现有绑定冲突、异库或无关发布者会阻止应用，不能为通过检查删掉原资料。

迁移按相同规范工程路径复用参考的 Markdown 绑定，但保留当前工程的 task ID、dataset ID、SQLite 账本与显示／续费设置；中央库已有发布来源用别名映射继续更新原固定键，不重建一套账本。应用前重新检查最新配置，避免覆盖对照后的人工作业。原笔记、人工正文及旧 Notion 审计不复制重写。

接管在中央发布锁内禁用参考发布开关，再将唯一发布者记录指向当前工程；发布者标记或锁异常时拒绝写入。该防护不替代停止未升级的旧程序。规则和模板继续共用，不覆盖成当前工程内的第二份。

## 阅读与维护项目

每个项目位于 `项目/项目名/项目.md`，保留固定 `id`，相关任务、历史、反馈和成果引用放在同一项目子目录。项目改名不重建身份；已有项目先匹配固定 ID、工程绑定和真实路径，不靠名称自动认领。读取已有记录不会重新写入内容。

项目卡保持四部分：总目标、需要你决策、需要你验收、目前要做的事。当前只展开本阶段未完成行动；后续阶段留在完整计划。人工事项独立展示，不能因阶段切换消失。未知时间和费用留空。

整体完成度由 AI 在接入、完整整理和重要进展收尾时主动估计。先固定当前版本目标与验收范围，再按主要成果及其重要性给出粗略百分比，默认约 5% 或 10% 粒度，保存 AI 来源、评估时间和简短依据。资料不齐时说明假设、主要不确定项以及能帮助确认的小检查，不能因不够精确而省略。重要结果、问题、范围或验收变化后复核，允许有依据地下调；小修不机械增加数值，也不据百分比推算工时。只有无法读取资料或身份未确定等执行阻塞才暂留空。

AI 估计最高 95%。100% 表示项目整体完成，只有用户针对当前约定范围明确确认后，AI 才可代为保存 manual 来源、确认时间、原话来源和成果版本。单项功能、某轮审阅或自动测试通过均不能自动把项目记为 100%，也不能自行换来源绕过上限。详细方法见当前工程 `skills/obsidian-project-manager/SKILL.md` 的“进度估计必须维护”。

从当前工程运行：

```sh
./pm --help
./pm check
./pm overview
./pm new-project --help
./pm add-task --help
./pm register-artifact --help
./pm submit-feedback --help
```

`check` 和 `overview` 为读取检查，不创建项目。管理命令使用当前工程的 `widget/data`，默认读取中央库，不使用副本运行数据覆盖当前计量身份。正式反馈需要真实用户意见、任务版本与内容摘要；AI 自测、未回复或已读不表示验收通过。

本机设置可选择已有库，并将本机目录绑定到已有项目固定 ID。未知的旧 Notion 对应关系先保留为未绑定，列入迁移核对，不擅自将名称相近项目合并。云端 Notion 页面不删除；本机旧配置与审计保留。旧集成代码、凭据读取器和同步器已移除，迁移工具只读取旧配置中的绑定 ID。正常运行无需 Notion 账号、凭据或 API。

## 成果与开发历史

当前进展应回答：做出了什么、放在哪里、实现了什么、哪些部分仍未验证。使用 `register-artifact` 登记真实工程路径、版本和摘要，或实际 HTTPS 地址；原文件留在工程，不复制进管理库。Mac 本机路径不能冒充手机可访问发布地址。

普通按钮、间距、文案修改合并在当前任务中，不逐条建反馈或历史。目标、范围、重要承诺变化，以及对明确版本的最终通过或正式退回，才保留正式用户意见。关键历史追加重要结果；纠错另加说明，不改写旧完成事实。计量刷新不生成开发历史。

## Skill 接续

沿用已安装 `obsidian-project-manager` Skill 的管理方法、中央规则与模板。AI 在每轮读取对应项目卡和当前任务，执行授权工作后更新当前状态；需要保存关键结果时使用当前工程 `./pm`。规则与中央库路径继续共用。仓库只提供当前 Markdown / Obsidian Skill，旧 Notion 项目 Skill 已移除。

Skill 不常驻执行。桌面只读取项目资料、组合已计量投入和发布摘要，不自主改变目标、批准验收或启动项目。

## 桌面看板

常态显示 Codex、账本和最多四个项目图标。后四位按真实本周 Token 排序，零用量管理项目可补空位，其余归“其他”；仅改变呈现，不改变总量、任务数或占比分母。三种主题与横竖两种胶囊位置保留。

项目外环表示本周 Token 占比，内环与4pt细进度条表示明确维护的完成进度。进度需保存来源、依据与复核时间，未知只显示轨道。悬停看状态、下一步、完成进度、占比；点击看概览／行动／投入。行动关联正式成果入口，长内容分页，无卡内滚动条。

Codex 与本期 Token 各为四行单页。官方剩余额度、自然周累计已用、本机 Token 和订阅金额估算采用不同口径，不相互倒推。估算采用用户选定的 `100% 周额度=$5`，不是官方 Token 单价或真实扣款。

## 可读账本与观察接口

本机计量数据库保留已观测事实；中央库的 `账本/每日`、`账本/周期` 为可读投影。相同固定键按绝对数值更新，不把扫描次数重复相加；周、月是同批事件的不同视图，不能再相加。唯一发布程序是当前工程 `widget/widget_backend.py --sync-markdown`。高频额度观测留 SQLite，显式请求才发布窗口摘要。

可选 HTTP 接口只监听本机，提供项目与任务的观察数据；不改变笔记、不刷新官方额度、不启动 AI，也不提供任意文件下载。胶囊直接读 Markdown，无需启动该接口。远程访问与写入不在本次范围内。
