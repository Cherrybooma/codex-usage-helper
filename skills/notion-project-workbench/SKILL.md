# Notion 项目工作台

项目管理为主，Token 是附属投入。沿用当前任务已经授权的项目、工作区与父页面；导入或维护请求授权范围内必要的页面、任务和事件更新。仅分析或本地草稿不授予云端写入；不修改全局 AGENTS，不自行发布、通知或建立定时任务。

## 导入已有项目

读取 [导入流程与清单](references/import.md)。先从该项目的说明、计划、实际代码、版本记录和产出核实事实，再生成 `project-import.json`；不要只套固定模板。用户已有管理主页面就在其下复用／新建项目页；没有时，在已授权可写的容器下建立「项目管理」。内部 Integration 没有可用父页面时，先完成清单并说明需要共享目标，不伪称已创建工作区根页面。

使用应用的 `widget/project_import.py --dry-run` 验证清单与本机产出，再执行同一清单导入。它复用父页、项目绑定、Tasks、Events 和 Usage Daily，补缺少的管理字段、保存本机文件夹身份，并重新读取 Notion 管理状态。用户也可在「项目与 Notion 设置 → 一键导入已有项目」选择清单和文件夹后运行；按钮负责执行配置，不在后台偷偷调用 AI。

没有本机导入程序时，使用可用 Notion 连接器按同一结构维护云端；报告本机绑定尚未完成。不能把只写入 Notion 当作胶囊已接入。已有项目本周没有用量时不捏造消耗；胶囊前两个入口固定为 Codex 账号和本期 Token；后面最多四个项目位从 Notion 管理项目中按真实本周 Token 降序选取，每次刷新重新排序。零用量管理项目可以补足展示位，同用量按稳定身份排序；其他管理项目及未纳入管理的本机目录归入「其他」。没有可用管理项目时回退本机有用量文件夹前四项。只调整展示，全部保留日志的 Token 和有用量文件夹任务数仍完整计入。不能为了显示图标改写计量。完整项目仍在管理页与项目设置中。

## 固定五部分

保留用户选择的顺序，首页保持简洁，完整信息留在关联记录中：

1. **愿景**：页首名称、Notion icon 和一小段最终预期结果。已有愿景没有变化就保留。
2. **待人工确认**：紧凑卡片，写清决定／验收什么、推荐什么、影响什么；只放需要人处理的事项。已决定的事项移出当前视图，记录保留。
3. **当前进展与下一步**：原生双栏。左栏说明当前阶段、完成事实、正式产出入口与实现／验收范围；右栏写具体下一行动和完成条件，不重复同名 Project 卡。
4. **历史开发记录**：近期 Events 列表和完整历史入口，保留时间、动作、结果、证据与 Project／Tasks 关系。
5. **Token 投入**：每项目的已计量每日／周摘要、统计范围和质量；不把投入当成完成度或收益。

建立／整理布局时阅读 [页面模板](references/template.md)，修改属性或关系时阅读 [字段约定](references/schema.md)。先读取页面与数据源身份，复用已有库与成果文档，不凭同名选中任意数据库。导入程序保留已有正文和原生视图；需要维护旧页面布局时，读取实际 block IDs 后只更新有关块，不能替换整页或追加第二套五部分。连接器不支持分栏时明确尚未落地，不把文字“两栏”当真实布局。

## 完成进度与产出

AI 可以评估完成进度：从完整愿景拆出少量交付里程碑，给出权重，依据已核实产出与验收为各里程碑估算完成程度，再计算加权百分比。保留里程碑、依据和评估时间；未知时留空。不能以 Token、目录大小、代码行数、已有 Tasks 完成率或模型自信作为项目完成度。界面只显示“完成进度”和数字，AI 估算性质留在记录与产品文档。

每阶段必须说明**产出是什么、放在哪里、实现了哪些功能／通过哪些验收**。Project 摘要与 Latest Output、Tasks Evidence、Events Evidence 指向同一正式产出或索引。已存在的 Notion 文档、验收页、仓库提交和 PR 先核查再复用；未发布的本机产出只写相对项目路径与结果摘要，标「本机待发布」。导入程序可建立真实 Notion 产出索引，不能假造 GitHub、下载或 localhost 分享链接。

项目 icon 必须是可显示的 emoji 或 HTTPS Logo，新建时设置；已有项目缺失时补充或明确待设置。Notion 没有全局 icon 必填约束，应用创建／绑定入口负责校验。生命周期 Status 和健康 Health 沿用该库现有选项。

## 推进、事件与同步

每次实际变化更新当前状态并追加 Events，先查稳定 Event Key；已完成 Tasks 不删除、不改名成下一任务。更正、重开或状态回退追加新事件，不能覆盖历史。顺序重试复用已有记录；键没有数据库唯一约束，同项目单写者维护。出现多个同键或创建结果不确定时，先重查并保留历史，不盲目追加或自动合并。

事件使用真实发生时间；旧事实原完成时间未知时，以实际回填时刻记录并注明「原完成时间未核实」，不编造过去日期。人工待办、受阻和完成数量只来自明确 Managed By=人类确认 的 Tasks；受阻属于待办子集，AI 任务不混入人工数。缺少管理者或查询不完整时保持未知。

双向数据流是 **Notion 管理状态 → 本机展示；本机已计量 Token 摘要 → Notion**。不由后台计量服务生成愿景、改任务或双向覆盖人的管理文本。项目周报用上海自然周；官方额度按实际窗口；会员月按已确认续费锚点。三者不混算，不从 Token 反推额度。周额度 100%=5 美元是用户选择的估算投入基准，不是账单或 API 价格。

云端只保存名称、管理摘要、关联、日期、计数和质量。原始日志、源码、对话、工具输出、绝对本机路径、会话／响应 ID 与凭据留在本机；不读取 auth.json 或认证环境变量。只同步 bound project/day 的绝对摘要，Token／质量不变不反复写入；日常处理变化行，完整历史每日或恢复／改绑时核对。已有周期配置只自动同步周／月 Token 摘要，额度窗口审计需显式开启；不因调用此技能新增独立额度页面。

完成后重新读取有关页面、关系、图标、正式产出、Tasks 和 Events，检查没有重复创建、历史保留、管理状态进入胶囊缓存、计量总数没有改变。说明实际写入与本机绑定结果；本地草稿、旧格式估算、未核实项与未发布成果分别说明。
