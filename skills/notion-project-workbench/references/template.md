# 给人看的五部分首页

先读取现有父页面，保留其页面身份、原生 icon、相关项目和现有视图。使用 Notion 原生布局和关联视图，能完成同一用途的既有区域直接复用。不要每次运行技能重建整个首页或再附加一套数据库。

## 1. 愿景

页面顶部使用原生页面图标、标题与一段简短愿景：为谁解决什么问题，项目成功后会得到什么结果。愿景由用户方向和已确认内容决定，不把 AI 的优化建议写成用户的新目标。

保留项目页中的目标与验收标准。多个项目的首页可显示总体愿景，具体项目卡链接各自的愿景；不要用装饰性 Banner 代替信息。

## 2. 待人工确认

主 Tasks 关联视图只筛选 Status 为待确认。卡片显示项目、要决定或验收的具体事项、成果／证据入口。需要人的选择或行动才能解除的阻塞，可以形成明确的待确认项并关联原阻塞任务；普通阻塞留在当前行动或风险，不因“阻塞”状态一律进入人工区，也不为此强增字段。

用户确认后更新原 Tasks 行，并追加 Events，保留原任务和旧事件；它可以因视图筛选退出此区域，不是从数据库删除。

## 3. 当前进展与下一步

单项目工作台直接展示当前阶段、已完成事实、剩余未知和 AI 下一项具体行动，再放关联 Tasks 看板／列表；不要再放一张同名 Project 卡重复页面标题。多项目入口才使用项目卡，显示各项目 icon、状态、当前目标、下一步和风险。

关联 Tasks 看板或列表只显示未完成项，并按优先级或明确日期排序。少量行动卡片便于扫描，长描述和计量细分放详情。

每个下一步应能执行并核查，例如“验证截图导出尺寸，并保存一份可分享样例”，而非“进一步完善”。进展摘要描述完成事实和剩余未知，不把活动量写成完成百分比。

## 4. 历史开发事件

默认显示按日期排序的 Events 原生列表，并提供可展开的原生时间线；条目显示时间、动作与实际结果、证据及 Tasks 关系。若连接器暂不支持时间线，保留原生列表并说明布局限制，不画一个假时间线。

事件按历史累积，任务重开、更正和状态回退保留新旧记录。当前 Tasks 看板的状态改变不能抹去 Events。历史回填事件要标出此次回填与原时间未核实，不把回填事件画成过去已经核实的完成记录。

## 5. 每项目 Token 投入

Usage Daily 关联视图按项目分组，筛选 Included = true，主要展示 Counted Tokens、日期范围与 Quality。投入区在管理区之后，点击再看输入、缓存、推理、来源和精确截止。

当前窗口为空与未读取数据分开表达。不要同时把旧停计摘要和新分配算成投入，或显示由 Token 猜测的收益与完成率。

## 轻量方法的参考边界

- [Notion Projects & Tasks](https://www.notion.com/help/guides/getting-started-with-projects-and-tasks)：项目与行动项分别组织，再用关系连接。
- [Basecamp Hill Charts](https://basecamp.com/hill-charts)：区分尚在解决未知的问题与已明确方案的执行，用历史状态帮助人查看变化。
- [Shape Up — Show Progress](https://basecamp.com/shapeup/3.4-chapter-13)：任务数量不能完整表达未知问题，过去的状态也有价值。

本工作台借鉴轻量关系、明确未知和保留历史，不复制整套 Shape Up，不强制六周周期，也不凭 Token 自动绘制 Hill Chart 或计算完成率。五部分顺序来自用户选择。
