# 给人看的五部分首页

先读取现有父页面，保留其页面身份、原生 icon、相关项目和现有视图。使用 Notion 原生布局和关联视图，能完成同一用途的既有区域直接复用。不要每次运行技能重建整个首页或再附加一套数据库。

## 1. 愿景

页面顶部使用原生页面图标、标题与一段简短愿景：为谁解决什么问题，项目成功后会得到什么结果。愿景由用户方向和已确认内容决定，不把 AI 的优化建议写成用户的新目标。

保留项目页中的目标与验收标准。多个项目的首页可显示总体愿景，具体项目卡链接各自的愿景；不要用装饰性 Banner 代替信息。

## 2. 待人工确认

主 Tasks 关联视图只筛选 Status 为待确认。采用紧凑的浅色卡片或原生 callout，显示“待决定／验收什么 → 推荐方案 → 影响”，成果入口紧邻事项。数据库内部字段和长说明留在详情。没有待确认事项时一行说明即可，不堆空卡片。

有 Decision、Recommendation、Impact 或对应字段时使用它们；否则写在任务正文，不为卡片排版强制增加属性。

需要人的选择或行动才能解除的阻塞，可以形成明确的待确认项并关联原阻塞任务；普通阻塞留在当前行动或风险，不因“阻塞”状态一律进入人工区，也不为此强增字段。用户已经决定的内容写入对应记录与事件，不继续显示为待确认。

用户确认后更新原 Tasks 行，并追加 Events，保留原任务和旧事件；它可以因视图筛选退出此区域，不是从数据库删除。

## 3. 当前进展与下一步

单项目工作台使用原生双栏：左侧展示当前阶段、已完成事实与阶段产出，右侧突出下一行动、完成条件与风险。关联 Tasks 看板／列表放在此区域，以少量未完成行动服务执行；不要再放一张同名 Project 卡重复页面标题。连接器无法建立分栏时说明限制，保留顺序草稿，不宣称已完成双栏。多项目入口才使用项目卡，显示各项目 icon、状态、当前目标、下一步和风险。

关联 Tasks 看板或列表只显示未完成项，并按优先级或明确日期排序。少量行动卡片便于扫描，长描述和计量细分放详情。

每个下一步应能执行并核查，例如“验证截图导出尺寸，并保存一份可分享样例”，而非“进一步完善”。进展摘要描述完成事实和剩余未知，不把活动量写成完成百分比。

### 阶段产出的小表

用现有项目文档／成果入口和 Evidence，默认不建新的 Outputs 库。已有 Artifacts 库能满足用途时复用其关联视图。首页只列近期相关产出，历史索引放详情。

| 阶段产出 | 入口与状态 | 实现与验收 |
| --- | --- | --- |
| 环形胶囊交互与说明 | 已存在的 Notion 交付页或经核实的仓库链接 | 图标入口、进度环、悬停概览；注明实际验收结果和未验证平台 |
| 本轮本机 UI 草稿 | 本机待发布 · `widget/preview/demo.html` | 新交互供本机审阅，尚未推送，不填写虚构公开链接 |

这些是格式示例，不代表某个项目已经产出或验收。对应 Tasks 记录完成条件、成果入口和验收结果；Events 记发生时间、实际变化与同一入口；Project 的 Outcome 或正文阶段索引提供总入口。不能仅有“做了什么”的活动列表。

## 4. 历史开发事件

默认显示近期、按日期排序的 Events 紧凑列表，并提供完整历史入口和可展开的原生时间线；条目显示时间、动作与实际结果、对应产出入口及 Tasks 关系。若连接器暂不支持时间线，保留原生列表并说明布局限制，不画一个假时间线。

事件按历史累积，任务重开、更正和状态回退保留新旧记录。当前 Tasks 看板的状态改变不能抹去 Events。历史回填事件要标出此次回填与原时间未核实，不把回填事件画成过去已经核实的完成记录。

## 5. 每项目 Token 投入

Usage Daily 关联视图按项目分组，筛选 Included = true，主要展示 Counted Tokens、日期范围与 Quality。投入区在管理区之后，点击再看输入、缓存、推理、来源和精确截止。

当前窗口为空与未读取数据分开表达。不要同时把旧停计摘要和新分配算成投入，或显示由 Token 猜测的收益与完成率。

项目页保留每日／周投入附属区。周期选择未决定时保留现有口径并展示明确的待确认项；已经确认的方案移出待确认区，继续沿用。例如采用自然周周报、官方实际额度窗口与会员续费月账期时，分别标明各自边界。实际续费锚点未知仅表示月核算 `needs_anchor`／待配置，不把月总数写零，也不重新询问已决定的周期方法。

跨项目周期核算和官方额度放在独立的“周期与额度”页面／数据库，以周记录、月核算、额度观测入口组织；不塞进单个项目五部分内，不创建 Projects 关系。项目页可链接独立入口，但不复制其周期记录。周、月复用同一份 Token 事实，不能相加；官方额度不能从 Token 推算，一个月也不等于四份周额度。

## 轻量方法的参考边界

- [Linear Method](https://linear.app/method/introduction)：简短项目说明、小而明确的行动、用实际成果呈现进展；这是当前主要方式。
- [Notion Projects & Tasks](https://www.notion.com/help/guides/getting-started-with-projects-and-tasks)：项目与行动项分别组织，再用关系连接。

采用 Linear 的轻量原则和用户指定的五部分顺序，不默认导入它的整套工作流程或两周周期。阶段产出、双栏和紧凑确认卡是本项目的展示选择，不声称是 Linear 的固定模板。
