# macOS 桌面组件

桌面组件是 Notion 项目管理的轻入口。常态只有图标，展开后先看项目目标、下一步和状态，再看 Token 投入。AI 管理方式及首页组织见 [项目管理说明](../docs/project-management.md)。

提供顶部横条、右侧竖条和桌面小框。三个开关可以同时开启，默认开启横条；共享每60秒更新的数据。默认位于桌面层，普通窗口可覆盖。显示选择和窗口位置会保存；恢复时按屏幕可见区域校正。

## 构建与启动

在项目根目录运行：

```sh
python3 -m venv .venv
.venv/bin/python3 -m pip install -r requirements-optional.txt
sh widget/build.sh
sh widget/run.command
```

最低运行系统 macOS 15。构建需 Swift 和包含 macOS 26 SDK 的开发工具；已在 Swift 6.2.4 / SDK 26.2 上编译。源码在 macOS26使用 Liquid Glass，macOS15使用 thinMaterial 毛玻璃回退；macOS26效果尚未实机验证。

应用在 `widget/build/用量小助手.app`，使用本机 ad-hoc 签名。不要将应用移出项目单独运行，它依赖项目 `.venv/bin/python3` 和 Python 数据层。目前推荐 `run.command` 启动；文件访问权限由系统与用户授权决定。

菜单栏或组件右键菜单可以切换三种形式。“项目与 Notion 设置…”也在这两个菜单中；找不到菜单时可双击 `设置.command`，或重新打开应用直接进入设置。关闭全部展示后刷新仍继续；菜单栏“退出用量小助手”停止应用。桌面小框可用图钉临时置顶，横条与竖条保持桌面层。

展示位置与视觉样式分别设置。样式有“液态玻璃”“Pulse 暗色”“经典白色”，默认液态玻璃；三种样式使用相同的数据与交互规则，不改变计量。

默认使用本机模式，无需填写 Notion Token。设置里可以选择项目目录和桌面显示形式；“启用 Notion 同步”关闭时隐藏连接表单，定时与手动同步均不会读取 Notion 凭据或联网。标准编辑菜单支持 ⌘V 粘贴；加载状态时输入框仍可编辑。

连接 Notion 时，密钥默认使用本应用专用钥匙串；也可明确选择自己的 Pages 密钥文件作为来源。设置显示所选文件名，后台仅在内存中提取 Token 进行认证，不上传整个文件；移动或删除来源文件会使连接暂停。可随时切换回钥匙串。

## 交互与显示

- 共用胶囊外框，模块布局为64pt，圆形交互区为54pt；常态只显示图标，不显示文字、数字或百分比。详情保留16pt主数字和辅助标签。
- 项目外环是本周 Token 占比，分母为全部本机已记录 Token；内环是明确的 AI／人工完成进度。未知只显示轨道，不能填成零。
- 胶囊前两个入口固定为 Codex 账号和本期 Token；后面最多四个项目位从 Notion 管理项目中按真实本周 Token 降序选取，每次刷新重新排序。零用量管理项目可以补足展示位，同用量按稳定身份排序；其他管理项目及未纳入管理的本机目录归入「其他」。没有可用管理项目时回退本机有用量文件夹前四项。只调整展示，全部保留日志的 Token 和有用量文件夹任务数仍完整计入。
- 项目图标使用 Notion 页面自身的 emoji 或 Logo；新建和绑定前必须验证图标。缺失时使用文件夹符号并在详情提示补充，不用项目名称首字代替图标。
- 悬停项目显示状态、下一步、完成进度、本周占比；点击项目后显示“概览／行动／投入”。概览展示状态、愿景、完成进度、占比；行动展示完整当前目标、人工待办／受阻／已完成、精简产出与进展及正式产出入口；投入展示本周／今日 Token、占比与估算美元。
- Codex 和本期 Token 都是单页，没有分类标签。Codex 显示周额度剩余、本周已用额度、本周 Token、估算投入；账本显示本周 Token、全量任务数、统计日期、去重响应次数。数字统一按行排列。
- 悬停180ms后展开，离开240ms后收起；点击保持、再次点击收起，其他模块可直接切换。详情内点击不关闭，外部点击或Esc关闭。
- 每个模块的悬停和点击范围只沿54pt可见圆形；圆外玻璃背景与模块间隙按住可拖动胶囊，拖动时收起详情。详情卡锚定所选模块并约束在屏幕可见范围，胶囊外透明区域穿透鼠标；展开不移动顶部锚点。
- 减少动态效果时移除移动动画；降低透明度或增加对比度时采用实色底色。

横条最多七个模块：Codex、账本、四个任务、“其他”。名称与数值在详情里显示。卡片内没有滚动容器或滚动条；空间不足时分页，长目标按连续段落完整展示。标签的整个矩形都是点击热区。玻璃高光位于内容下方，不降低文字对比度。Codex 图标固定表示剩余，不再通过滚轮改换指标。桌面小框保留低于5%合并到其他的分组。

详情卡采用已通过的 [HTML 排版稿](preview/layout-review.html)：宽360pt、四边内边距20pt、内容组间距16pt、标签与正文间距6pt。辅助标签12pt、正文和日期14pt、标题与主数字16pt，正文行高22pt。各入口统一按行展示指标，人工待办用轻量横向文字，完成进度保持4pt细条。卡片随内容自然收紧，高度不超过520pt且受屏幕可用空间约束；短屏减少每页内容，不缩小字号。三种主题共用同一套排版。

`Development Progress` 是 0–100 的明确评估值；`Progress Source` 标记 AI估算或手动。Skill 根据里程碑和实际产出维护估算依据与复核时间，不用 Token 或待办完成率推算。旧版没有来源字段的合法明确数值保持手动来源；缺失或非法值保持未知。UI 使用“完成进度”，4pt 细条，百分比位于条外右上方。今日用量按统计终点对应的上海日期和记录内部时间汇总。

Tasks 为可选数据源。人工事项仅统计 `Managed By = 人类确认` 的任务；AI 任务不混入。受阻属于未完成事项的子集。未配置、未分类、结构异常或缓存过期时数量未知，不显示虚构的零。归档或隐藏项目的历史 Token 仍在本机总数中。

## 数据层

复用根目录 `codex_usage.py`，扫描 `sessions` 与 `archived_sessions`。默认 `CODEX_HOME` 或 `~/.codex`；任务根目录默认 `~/Documents`。按任务根目录第一级文件夹合并子目录，未知目录及任务根目录之外的路径单独分类，不猜测业务归属。

界面的本周是北京时间周一00:00到下周一00:00；每次刷新固定UTC终点，只计入终点之前。CLI扫描器默认最近滚动7天，两种时间窗口不同。

手动运行数据层：

```sh
.venv/bin/python3 widget/widget_backend.py --help
.venv/bin/python3 widget/widget_backend.py --offline
# 指定自己的任务根目录：
.venv/bin/python3 widget/widget_backend.py --task-root /path/to/projects --offline
```

原生应用可在“项目与 Notion 设置…”选择持久项目根目录。CLI 的 --task-root 对本次执行优先。

只有开启 Notion 同步并完成连接后，才每5分钟在独立进程中同步摘要，不阻塞每分钟本地扫描。项目每日摘要只同步已绑定项目；独立周期页另保存整体投入和项目／模型摘要。可以显式绑定已有项目，或创建并绑定一个项目；详细连接、数据与重试口径见 [Notion 说明](../docs/notion.md)。

项目属性、任务和开发事件由 [notion-project-workbench 技能](../skills/notion-project-workbench/SKILL.md)在用户安排的工作中维护，或由人在 Notion 编辑。每次实际推进追加事件，已完成任务保留。尚未启用定时 Notion Custom Agent；桌面后台不会自行完成任务、生成管理结论或改写项目目标。

## 周记录与会员月核算

菜单「周期核算…」提供自然周、实际额度窗口和会员月账期的独立入口。自然周为上海时间周一 00:00 至下周一 00:00；会员月以手动确认的最近一次续费时间为锚点，逐月按原日期与时间划分。一个月不能按四周相加，周／月两份视图也不能再相加成额外消耗。

未填写续费时间时，月账期显示待配置。只知道续费日期时以上海当天零点为边界，明确标为日粒度估算；其他推算月份不等于每次真实续费均已核对。日期未知、旧格式估算、无法识别记录和窗口无用量分别显示，不使用零值掩盖未知。

周期汇总从扫描器统一接受的计量事件按内部时间重分组，保留窗口前的旧累计基线、响应去重和 fork 继承处理。默认查看当前及此前共 12 个自然周／会员月；本机 Token 周期缓存最多 5 分钟，保存续费锚点会使旧缓存失效。「刷新核算」强制重算，不读取认证文件、不触发 Notion 写入。

```sh
mkdir -p validation
python3 widget/widget_backend.py --accounting-summary --output validation/accounting.json
```

已配置周期账本时，常规同步更新周／月 Token 摘要；不新增独立额度页，额度高频观测留 SQLite。已有额度窗口云端页和待发送审计队列保留，默认不再自动更新；显式执行 `widget_backend.py --sync-notion --quota-window-audit` 才同步窗口审计。报告省略旧的全零空闲窗口，不将零额度截止时间滚动解释成福利重置，原始本机观测仍完整保留。

普通同步只处理变化摘要与待发送队列。完整历史对账每天执行，重新绑定、连接恢复或手动强制同步会立即对账。仅统计截止时间推进、Token 和质量未变化时不写云端，最新接受时间仍在本机用于防止旧扫描倒退。规则见 [Notion 说明](../docs/notion.md)。

## 官方额度与本周累计

数据层寻找官方Codex CLI，启动短暂的stdio app-server，只调用 `account/rateLimits/read` 后关闭。认证由官方客户端处理，本项目不直接打开认证文件；不向官方接口发送日志或项目统计。

额度详情固定四行，优先选择 `codex` bucket，按时长识别周窗口。“周额度剩余”为 `100 − used_percent`；本周已用来自自然周观测累计，二者窗口不同。额度缺失保持未知；接口失败保留带旧缓存标记的读数，超过3分钟或重置时间视为过期。

估算投入按用户定义的 `100% 周额度 = $5` 折算，再按本周 Token 占比分摊给项目。它不是官方价格或实际扣款。确认下限显示 `≥`，完整观测仍属于估算，歧义数据保持未知；计算例子见 [根 README](../README.md#额度与本周超额)。

本周累计只加已观测使用增量。确认提前重置后，保留旧消耗，加入新窗口已用；重置本身不记成100%。五小时窗口不加入周累计。若官方窗口从上一自然周开始，不能把包含上周消耗的整个百分比搬到本周。

首次采集、观测间隔、重置前缺失读数、部分重置或修正、窗口截止变化、套餐或额度分类变化都可能使记录不完整或有歧义。累计不足或等于100%显示未超额，含义仅限已记录部分；可确认的超额下限显示≥，有歧义则待核实。不同容量的额度不能直接相加。详细口径见 [项目说明](../README.md#额度与本周超额)。

## 本地文件

| 文件 | 内容 |
| --- | --- |
| `data/latest.json` | 当前界面统计快照 |
| `data/official-latest.json` | 最近一次官方额度观测 |
| `data/quota-history.sqlite3` | 保存的额度观测与周期历史 |
| `data/display-settings.json` | 三种展示形式开关 |
| `data/app-settings.json` | 项目根目录、Notion 同步开关、续费锚点与精度、可选密钥来源文件路径（不含 Token） |
| `data/accounting.json` | 自然周与会员月汇总的本地缓存 |
| `data/positions.json` | 归一化的窗口位置 |
| `data/project-registry.json` | 稳定任务与匿名来源数据集身份 |
| `data/daily-ledger.sqlite3` | 已观测项目每日摘要 |
| `data/notion-config.json` | 项目与周期数据库、周期页入口、同步起点和绑定，不含凭据 |
| `data/notion-state.json` | 项目缓存、待同步摘要与幂等指纹 |
| `data/window-state.json` | 本组件的层级、尺寸、位置与展开状态 |

上述目录被Git忽略。不会采集其他应用的屏幕内容。退出后可备份并删除 `data/`，下一次启动重新建立记录；删除历史会丢失累计基线、绑定与来源身份；重新生成来源身份后再同步可能产生另一套来源的摘要，建议保留备份。

## 演示与检查

`preview/demo.html` 使用固定演示数据，不访问真实日志，可直接在浏览器打开。它展示外观和交互，不能当成真实用量验证。

从项目根目录运行 `node widget/test_preview_events.cjs` 检查预览卡片重绘后的点击冒泡；只使用 Node 内置模块，模拟 DOM 事件路径，不访问日志、不启动浏览器，也不写结果文件。

Python与Swift检查命令见 [根README](../README.md#检查与测试)。测试使用模拟记录与状态检查。桌面坐标点击的自动化工具存在窗口可见性限制；可访问性点击、网页点击和状态机检查已执行，不将它们说成所有鼠标场景均已验证。
