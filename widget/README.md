# macOS 桌面组件

提供顶部横条、右侧竖条和桌面小框。三个开关可以同时开启，默认开启横条；共享每60秒更新的数据。默认位于桌面层，普通窗口可覆盖。显示选择和窗口位置会保存；恢复时按屏幕可见区域校正。

## 构建与启动

在项目根目录运行：

```sh
python3 -m venv .venv
.venv/bin/python3 -m pip install -r requirements-optional.txt
sh widget/build.sh
sh widget/run.command
```

最低运行系统 macOS 15。构建需 Swift 和包含 macOS 26 SDK 的开发工具；已在 Swift 6.2.4 / SDK 26.2 上编译。源码在 macOS26使用 Liquid Glass，macOS15使用 thinMaterial 毛玻璃回退；macOS26效果尚未实机验证。

应用在 `widget/build/用量小助手.app`，使用本机 ad-hoc 签名。不要将应用移出项目单独运行，它依赖项目 `.venv/bin/python3` 和 Python 数据层。目前推荐 `run.command` 启动；文件访问权限由系统与用户授权决定。

菜单栏或组件右键菜单可以切换三种形式。“项目与 Notion 设置…”也在这两个菜单中；找不到菜单时可双击 `设置.command`，或重新打开应用直接进入设置。关闭全部展示后刷新仍继续；菜单栏“退出用量小助手”停止应用。桌面小框可用图钉临时置顶，横条与竖条保持桌面层。

默认使用本机模式，无需填写 Notion Token。设置里可以选择项目目录和桌面显示形式；“启用 Notion 同步”关闭时隐藏连接表单，定时与手动同步均不会读取 Notion 凭据或联网。标准编辑菜单支持 ⌘V 粘贴；加载状态时输入框仍可编辑。

连接 Notion 时，密钥默认使用本应用专用钥匙串；也可明确选择自己的 Pages 密钥文件作为来源。设置显示所选文件名，后台仅在内存中提取 Token 进行认证，不上传整个文件；移动或删除来源文件会使连接暂停。可随时切换回钥匙串。

## 交互与显示

- 共用胶囊外框、64pt圆形模块、16pt主数字与10pt辅助标签。
- 按本周Token从高到低显示前三个真实任务，其余任务归入“其他”。不足三个不补虚构数据。
- 常态显示项目头像或 Logo 与占比，展开查看完整名称、Notion 管理状态与详情。
- 任务详情包括Token、排名、真实会话数、响应数；快照不含旧累计估算且响应数非零时展示平均Token/响应。
- 悬停180ms后展开，离开240ms后收起；点击保持、再次点击收起，其他模块可直接切换。详情内点击不关闭，外部点击或Esc关闭。
- 每个模块只有一个按钮；背景玻璃、分隔线不接收点击。横条预留固定展开尺寸，透明空白区域穿透鼠标；展开不移动顶部锚点。
- 减少动态效果时移除移动动画；降低透明度或增加对比度时采用实色底色。

横条最多六个模块：当前周额度剩余、本周记录、三个任务、其他。竖条保持列宽展开；内容超过屏幕高度时滚动。桌面小框保留低于5%合并到其他的分组，所有百分比继续以全部本机已记录Token为分母。

## 数据层

复用根目录 `codex_usage.py`，扫描 `sessions` 与 `archived_sessions`。默认 `CODEX_HOME` 或 `~/.codex`；任务根目录默认 `~/Documents`。按任务根目录第一级文件夹合并子目录，未知目录及任务根目录之外的路径单独分类，不猜测业务归属。

界面的本周是北京时间周一00:00到下周一00:00；每次刷新固定UTC终点，只计入终点之前。CLI扫描器默认最近滚动7天，两种时间窗口不同。

手动运行数据层：

```sh
.venv/bin/python3 widget/widget_backend.py --help
.venv/bin/python3 widget/widget_backend.py --offline
# 指定自己的任务根目录：
.venv/bin/python3 widget/widget_backend.py --task-root /path/to/projects --offline
```

原生应用可在“项目与 Notion 设置…”选择持久项目根目录。CLI 的 --task-root 对本次执行优先。

只有开启 Notion 同步并完成连接后，才每5分钟在独立进程中同步摘要，不阻塞每分钟本地扫描。未绑定项目留在本机。可以显式绑定已有项目，或创建并绑定一个项目；详细连接、数据与重试口径见 [Notion 说明](../docs/notion.md)。

## 官方额度与本周累计

数据层寻找官方Codex CLI，启动短暂的stdio app-server，只调用 `account/rateLimits/read` 后关闭。认证由官方客户端处理，本项目不直接打开认证文件；不向官方接口发送日志或项目统计。

额度详情包含当前窗口已用、本周已记录累计、本周超额、重置时间与可用的五小时剩余。优先选择 `codex` bucket，按窗口时长区分当前周窗口与短窗口。额度缺失显示未取得；接口失败保留旧缓存并注明，超过3分钟或重置时间的快照视为过期。

本周累计只加已观测使用增量。确认提前重置后，保留旧消耗，加入新窗口已用；重置本身不记成100%。五小时窗口不加入周累计。若官方窗口从上一自然周开始，不能把包含上周消耗的整个百分比搬到本周。

首次采集、观测间隔、重置前缺失读数、部分重置或修正、窗口截止变化、套餐或额度分类变化都可能使记录不完整或有歧义。累计不足或等于100%显示未超额，含义仅限已记录部分；可确认的超额下限显示≥，有歧义则待核实。不同容量的额度不能直接相加。详细口径见 [项目说明](../README.md#额度与本周超额)。

## 本地文件

| 文件 | 内容 |
| --- | --- |
| `data/latest.json` | 当前界面统计快照 |
| `data/official-latest.json` | 最近一次官方额度观测 |
| `data/quota-history.sqlite3` | 保存的额度观测与周期历史 |
| `data/display-settings.json` | 三种展示形式开关 |
| `data/app-settings.json` | 项目根目录、Notion 同步开关、可选密钥来源文件路径（不含 Token） |
| `data/positions.json` | 归一化的窗口位置 |
| `data/project-registry.json` | 稳定任务与匿名来源数据集身份 |
| `data/daily-ledger.sqlite3` | 已观测项目每日摘要 |
| `data/notion-config.json` | 数据库、同步起点和绑定，不含凭据 |
| `data/notion-state.json` | 项目缓存、待同步摘要与幂等指纹 |
| `data/window-state.json` | 本组件的层级、尺寸、位置与展开状态 |

上述目录被Git忽略。不会采集其他应用的屏幕内容。退出后可备份并删除 `data/`，下一次启动重新建立记录；删除历史会丢失累计基线、绑定与来源身份；重新生成来源身份后再同步可能产生另一套来源的摘要，建议保留备份。

## 演示与检查

`preview/demo.html` 使用固定演示数据，不访问真实日志，可直接在浏览器打开。它展示外观和交互，不能当成真实用量验证。

Python与Swift检查命令见 [根README](../README.md#检查与测试)。测试使用模拟记录与状态检查。桌面坐标点击的自动化工具存在窗口可见性限制；可访问性点击、网页点击和状态机检查已执行，不将它们说成所有鼠标场景均已验证。
